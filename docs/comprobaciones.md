## Observaciones reales y límites

- **C13** no se ocultó: la corrida completa tuvo un fallo intermitente en `process-restart` (`REVIEW vencido=false`, comparación de id de pregunta). Al ejecutar únicamente esa suite pasó 5/5. No se modificó código para forzar el resultado.
- **C14** los cuatro fallos de Playwright son de expectativas contra la UI actual: el test espera una redirección/heading distinto después del registro y un `textarea rows="3"` cuando la UI actual usa `rows="1"`. Se dejan documentados; corregirlos exigiría tocar pruebas o código fuera del alcance de esta entrega.
- **Participantes:** no hay participantes humanos. Los 30 alumnos de la BD existente son datos de prueba; los 4 rivales del mock son bots. El cliente REST es real y consulta la API real.
- **Partida en vivo real:** no se creó una partida nueva en la BD para no alterar datos funcionales. Las capturas de juego en vivo son del modo mock; las capturas reales cubren login, dashboard, historial y cliente REST.
- **Docker Hub:** tras autorización expresa, se publicaron API/web en `keril777` con etiquetas versionadas y latest; la v1 anterior se conservó. Se verificó acceso público, arranque, login y REST sobre la BD existente. La incompatibilidad camilitofge/Railway queda como historial. No se repitió una partida nueva ni la suite entera sobre estas imágenes.
- **Datos:** la BD conserva 1 cuestionario, 2 salas finalizadas, 60 participantes y 161 respuestas después de todas las comprobaciones.
- **Recuperación tras reinicio:** Docker Desktop volvió a estar disponible, pero PostgreSQL quedó detenida; se inició el mismo contenedor, sin recrearlo. La imagen web encontrada estaba en modo demo: se reconstruyó con las variables reales mediante `start.ps1` y se verificó login real. No usar `docker compose build` sin cargar las variables `VITE_*`; `-SkipBuild` no actualiza las variables incorporadas a una imagen anterior.
- **Arranque de Docker Desktop:** se añadió detección de sus rutas habituales e intento de apertura. El intento inicial fue interrumpido por el reinicio del entorno; no se considera validado de extremo a extremo el arranque del motor desde apagado. El arranque con motor disponible sí está verificado. No se apagó Docker para repetirlo, para no interrumpir PostgreSQL.
- **Validación manual pendiente:** una partida real nueva con varios usuarios/dispositivos y participantes humanos no fue ejecutada; no se sustituye con las capturas mock.
- **Incidente anterior (C19):** el error HTTP 500 del motor Docker se observó antes de la revisión de red. Posteriormente el motor volvió a responder y pasaron C20 y la repetición de parada/arranque C06. Se conserva el registro fallido; no se presenta como éxito. El bloqueo de Word se liberó y se regeneró `docs/entrega-final.docx`; la copia alternativa anterior se conserva como histórica.
- **Configuración final de BD:** red externa `profelink-data`, DNS `profelink-pg-test-answers:5432`. El contenedor sigue conectado también a `bridge`; no se recreó ni se cambió el volumen. Ya no se usa `host.docker.internal` para la conexión de la API Dockerizada.
